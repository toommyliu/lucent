Architecture plan

Adopt a small, side-effect-free @lucent/core package

Move Lucent-owned domain logic out of app/src/shared without turning it into a schemas-only package. Effect Schema codecs should sit beside defaults, pure helpers, selectors, compatibility transforms, and stable AQW-facing records.

Prepared for Lucent Date: 2026-07-06 Reference: private local reference First slice: combat profiles

Goal

Boundary

Create a stable core package shared by main, renderer, preload, scripting, tests, and future tooling. It should own canonical Lucent data, Effect schemas/codecs, defaults, compatibility transforms, and pure domain helpers.

Non-goal

Discipline

Do not create a generic dumping ground named "schemas". Do not move Electron, DOM, Solid, storage IO, IPC runtime handlers, or AQW bridge side effects into the package.

Why now

Leverage

Combat profiles already cross persistence, IPC, UI, game runtime, and scripts. Keeping that model in app-local shared files forces duplicate parsing and scatters behavior that should be predictable under load and failure.

What to borrow from t3code

Package by ownership, not file type.

t3code's contracts package is not a folder per concept like "types", "schemas", and "normalizers". It uses cohesive modules such as settings.ts, keybindings.ts, project.ts, and ipc.ts. Lucent should follow that: one domain module until the domain earns a split.

Schema values anchor the module.

t3code exports Effect Schema values and derives types from typeof SomeSchema.Type, but the same module can also export defaults, branded constructors, small helpers, and compatibility functions.

Normalize while decoding.

Instead of decoding and then hand-normalizing everywhere, use Schema.decodeTo, Schema.withDecodingDefault, bounded checks, branded IDs, and encode transforms so legacy input becomes canonical output.

Keep decoder compilers hoisted.

t3code even has an oxlint rule against compiling schema decoders inside hot functions. Lucent should compile decoders once per module for IPC, persistence, and AQW adapters.

Decode old data, encode clean data.

A codec can accept legacy shapes, tolerate missing fields, trim strings, apply defaults, and then write only the current shape back to disk or across IPC.

Name and identity

Use @lucent/core

@lucent/contracts is accurate for schemas and IPC payloads, but too narrow for future pure logic. @lucent/core says this package owns Lucent's canonical, side-effect-free domain layer, not just wire validation.

Avoid @lucent/internal

internal describes visibility, not responsibility. It invites a junk drawer. core gives the package a center of gravity while still being private to the monorepo.

Current Lucent pressure points

  • app/src/shared/combat-profile-model.ts defines interfaces and schemas separately, which invites drift.
  • app/src/shared/combat-profile-normalization.ts repeats small unknown-record helpers, decode options, trimming, clamps, defaulting, and legacy handling by hand.
  • settings.ts, hotkeys.ts, and army.ts each own local parsing styles.
  • renderer/game/flash/payload.ts and selectors.ts are correctly tolerant, but should be treated as AQW edge adapters, not general core-domain inputs.
  • IPC descriptors already use Effect Schema, so moving descriptors to core is low-friction once package imports exist.

What can live in core later

Layer Examples Rule
Contracts Effect schemas, codecs, branded IDs, versioned persisted shapes, IPC payload schemas. Anything crossing a process, package, storage, or scripting boundary needs a runtime contract.
Defaults Default combat profile, default settings, default hotkeys, bounded numeric limits. Defaults live beside the schema that validates them.
Pure behavior Lookup helpers, selector matching, hotkey formatting, profile ID creation, stable sorting, compatibility transforms. Allowed only when deterministic and free of Electron, DOM, timers, IO, bridge calls, or service state.
Stable AQW models Normalized item, monster, player, aura, quest, and selector shapes used by scripts and UI. Core owns the stable output shape. Flash object spelunking stays in renderer adapters.
Runtime algorithms Potentially pure combat-profile step selection or condition evaluation. Only move it if dependencies are passed as plain data/functions. Anything calling the game bridge stays out.

Boundary rules

Area Belongs in @lucent/core Stays in app packages
Domain models Combat profiles, app settings, hotkeys, window IPC payloads, scripting API payload types. Solid component state, Electron service state, renderer-only view models.
Validation Effect schemas, codecs, branded IDs, bounds, defaults, legacy transforms. File-system side effects, Electron IPC registration, UI form event handling.
Normalization Pure, deterministic canonicalization of first-party persisted or IPC data. Long-running recovery, user prompts, logging, telemetry, retries.
AQW raw data Stable output records and shared selector shapes once decoded. Direct Flash object traversal, packet timing, bridge calls, runtime caches.

Normalization model

Raw input JSON files, IPC payloads, script args, Flash bridge values.
Edge codec Decode once with the correct tolerance policy.
Canonical type Branded IDs, bounded numbers, defaults, trimmed strings.
Pure helpers Selectors, lookup, compare, serialization, cloning.
Encode Persist and transmit only the current canonical wire shape.
Important distinction:

First-party Lucent data should be normalized by core codecs. AQW packet and Flash object data should use thin adapter modules that produce stable core records. Do not pretend unstable external object keys are first-party domain models.

Combat profiles first slice

  1. Add @lucent/core with effect as its only runtime dependency.
  2. Put the combat profile schema, type exports, defaults, tolerant decode, canonical encode, and tiny lookup helpers in a single packages/core/src/combatProfiles.ts module.
  3. Derive exported TypeScript types from schemas where possible. Keep explicit interfaces only when recursive or readability constraints make schema-derived types painful.
  4. Replace manual normalizer internals with schema transforms: trim IDs and labels, default cooldown and delay, clamp skill and wait values, decode legacy skipIfUnavailable, and require at least the generic profile after decode.
  5. Keep temporary re-export shims in app/src/shared while imports migrate. Remove them in a follow-up once stable.
  6. Extract a second combat-profile file only after there is a concrete reason: a hot path that needs isolation, tests that have become hard to aim, or an independent subdomain with multiple callers.

Example codec direction

export const CombatProfileId = TrimmedNonEmptyString.pipe(
  Schema.check(Schema.isPattern(/^[a-z0-9][a-z0-9._-]*$/u)),
  Schema.brand("CombatProfileId"),
);

export const CombatProfileStep = Schema.Struct({
  id: TrimmedNonEmptyString,
  skill: SkillIndex,
  conditions: Schema.Array(CombatProfileCondition).pipe(
    Schema.withDecodingDefault(Effect.succeed([])),
  ),
  cooldownMode: Schema.optionalKey(CombatProfileCooldownMode),
  waitMs: Schema.optionalKey(WaitMs),
});

export const CombatProfile = LegacyCombatProfileSource.pipe(
  Schema.decodeTo(
    CombatProfileWire,
    SchemaTransformation.transformOrFail({
      decode: decodeLegacyProfileToWire,
      encode: encodeProfileWire,
    }),
  ),
);

The exact split may differ, but the principle should hold: call sites receive a canonical profile, not a raw object plus a TODO to normalize it later.

Migration phases

Package scaffold

Add workspace package, exports, tsconfig, package scripts, and a small baseSchemas.ts with reusable trimmed strings, bounded ints, and branded ID constructors.

Combat core module

Port the current combat profile model and normalizer into one schema-first module. Add decode and encode tests using representative legacy, malformed, and canonical payloads.

Import migration

Point main persistence, renderer UI, preload bridge, script combat API, and tests at @lucent/core/combatProfiles. Keep shared re-exports for one transition.

IPC relocation

Move IPC descriptor types and channel descriptors into core only if they stay pure data and schemas. Leave Electron-specific handler creation in app/src/main.

Settings and hotkeys

Convert app settings and hotkeys to schema-defaulted codecs, reducing local helpers like decodeOrElse and hand-built record traversal.

AQW adapter cleanup

Extract shared raw-value helpers for AQW bridge data, but keep edge tolerance explicit. Stable records can move to core; raw packet quirks stay near the runtime.

Testing policy

  • Add package-local tests for each public schema: canonical decode, legacy decode, malformed input, encode output, and defaulting.
  • Keep IPC handler tests focused on "the descriptor decodes at the boundary", not on re-testing every domain field.
  • Use representative legacy combat profile JSON fixtures before changing persistence behavior.
  • Add a guard against inline schema compiler calls in hot code, either by adapting the t3code oxlint rule or documenting it until a local rule is worth maintaining.

Acceptance criteria

  • New combat profile features import canonical domain APIs from @lucent/core, not app/src/shared.
  • Persisted legacy profile files decode and re-save as canonical versioned profile libraries.
  • Main, renderer, preload, and script API agree on the same schema values for payloads.
  • Manual unknown-record walkers decrease in first-party data paths.
  • pnpm format, pnpm lint, and pnpm typecheck pass after each migration slice.

Risks and choices

Risk Mitigation
Over-centralizing every helper into core. Only move values that cross package or process boundaries. Keep runtime-only helpers local.
Schema transforms hide too much behavior. Name codecs by intent, write focused tests, and keep complex transforms in small pure functions next to the schema.
AQW payloads are too messy for strict schemas. Use adapters for raw AQW data and stable core records for normalized outputs. The tolerance stays visible at the edge.
Import churn during active combat-profile work. Start with re-export shims, then migrate call sites in one small slice at a time.
